## 3. Environment gotchas (real, will bite you)

- **`python` and `python3` hit the Microsoft Store stub and silently do nothing** —
  both resolve to `AppData\Local\Microsoft\WindowsApps\`. **Use `py` instead**
  (verified 2026-09-22): the Windows launcher finds the real Python 3.14.7 and sees
  every installed package. `py -m flame.models.suppression`, `py scripts/build_all.py`.
  The full path `C:/Users/anteu/AppData/Local/Python/bin/python3.exe` also works but
  is not needed. Run everything from the repo root, never from a subfolder.
- If accented output crashes a print, set `$env:PYTHONIOENCODING="utf-8"` once per
  terminal.
- Installed and working: pandas 3.0.6, numpy 2.5.3, openpyxl 3.1.5 (for `.xlsx`),
  xlrd 2.0.2 (for legacy `.xls`).
- Shell is **PowerShell** primarily; a Git Bash tool is also available. In Git Bash,
  Windows paths with backslashes get mangled — use `/c/Users/anteu/...` form.
- Some NASA CSVs are **Windows-1252, not UTF-8** (confirmed: PSI-69 `FLEX.csv`).
  `pd.read_csv(..., encoding='cp1252')`. Others have a UTF-8 BOM — use
  `encoding='utf-8-sig'` (confirmed: PSI-26, PSI-25).
- Console printing of DataFrames can crash on Greek/µ characters under cp1252 —
  see the PYTHONIOENCODING note above.

deep trees the user screenshots the site's folder view and we hand-write a
`layout.json` mapping `{zip filename: site path}`, passed to `unflatten.py`.
10 investigations have one.

## 6. Usable datasets — the ones with real per-test outcomes

All paths relative to `combustion_science/`. "Rows" = usable per-test rows.

### Droplet track (same hardware family: ISS Combustion Integrated Rack / MDCA)

**PSI-69 — FLEX-1, suppressant study.** `microgravity_investigation/PSI-69/csv/FLEX.csv`
274 burns. Methanol (157) + heptane (117), O2 mole fraction 0.12–0.34, **CO2 added in
123 burns, helium in 50**. Columns: initial diameter, ambient pressure (mmHg), full gas
composition, extinction diameter, burning rate, burn time, and `Test end` =
**Extinction (186) / Disruption (61) / Completion (27)**.
→ Cleanest label in the whole catalog, and the only dataset about *fire suppression*.
→ Caveats: cp1252 encoding; the 61 "Disruption" rows are failed tests (droplet broke
up / drifted) — exclude from the label, leaving ~213.

**PSI-39 — CFI, cool flames.** `microgravity_investigation/PSI-39/csv/CFI_DataSummary_Spreadsheet_Jan2021.xlsx`
227 burns, sheet **`DATA`** (sheet `Master Sheet` has the conditions, joined on
`Flex Number`). Columns: `D0`, `Dext hot`, `Dext cool`, `k_hot`, `k_cool`,
`Pressure (atm)`, reignitions, HF burn time, radiometer peaks. Fuels: n-dodecane (80),
two dodecane/iso-dodecane blends (103), farnesane (44). Pressures 0.5–5 atm, 52
helium-diluted.
→ Label: 120 of 227 have a cool-flame extinction diameter, 107 don't → binary
"did a cool flame persist after hot-flame extinction", roughly balanced.
→ Caveat: `Pressure` is text with inconsistent spelling (`.5 atm` vs `0.5 atm`,
one `3400%` typo in a sibling file — check for similar).

**PSI-117 — FLEX, cool flames.** `ground_investigation/PSI-117/csv/` (9 CSVs)
~93 rows. Same schema as PSI-39, but these are messy Excel/Origin exports with several
fuel/source blocks laid out **side by side in one file**, so pandas produces
`Do`, `Do.1`, `Do.2`… Cleaning approach: identify each block's column triplet,
`dropna` on its key column, tag with fuel/source, append.
Scalar files: `MST_2024_Dext.csv`, `MST_2024_Kavg.csv`,
`PROCI_2023_Alkane_Extinction_Diameter_1atm.csv`,
`PROCI_2023_C12_Extinction_Diameter_vs_pressure.csv`.
Time-series files (NOT scalar — flame diameter/radiance vs time within one burn):
`MST_2024_Burning_history_Flame_diameter.csv`, `MST_2024_Radiance_Flame_Diameter.csv`,
and the three `PROCI_2019*`/`PROCI_C12_2019*` files.
`ReadMe_List_of_Data.xlsx` is NASA's own index of what each file is — read it first.
→ Note: filed under `ground_investigation/` but NASA calls it a Flight Investigation.
Filing quirk, not a mistake to fix blindly — ask the user before moving it.

### Gas-burner track

**PSI-159 — ACME CFI-G.** `microgravity_investigation/PSI-159/csv/`
`CFI-G_Normal Flames.csv` (179 tests) + `CFI-G_Inverse Flames.csv` (154 tests) = 333.
Fuels: ethane/propane/butane, neat and N2-diluted. Columns: fuel, XO2 before/after,
pressure, fuel fraction, flow rate, adiabatic flame temp `Tad`, `Zst`, hot ignition,
burn time, peak burner temp, flame colour, comments.
→ Label: **`Self-ext or flow term`** = SE (flame died on its own) vs FT (crew cut the
flow). Directly observed, no threshold invented. Also `Hot ignition` yes/no.
→ Caveats: raw file has ~1000 lines but only 154 real inverse tests (blank Excel rows —
`dropna(subset=['Test'])`); values are inconsistent (`Yes`/`yes`/`flash`, `-` for
missing); `Cool flame?` column is 96% empty.
→ PSI-157 was this experiment's sister on paper (same team, same burner, propane/
n-butane/n-pentane), but **NASA publishes no data for it** — checked 2026-09-22, the
folder has been deleted. Do not go looking for it again. PSI-159 is the whole
sustainment module.

### Smoke / detection track

**PSI-101 — SAME-R.** `microgravity_investigation/PSI-101/csv/`
`SAME-R.csv` = 109 test points but **conditions only** (material, inlet velocity,
duration, aging/mixing times). The outcomes are in
**`Combined SAMER Results 06 02 14.xlsx`**, 43 sheets, ~80 instrument columns per test:
particle counter at 3 sizes, ionization-detector moment, DustTrak mass, sample
temperature. Sheets that matter: `Reduced data sheet`, `Reduced Data with ISS Det`,
`Reduced Data with STS Det`, `detection June 14`, `detection Mar 14`, `Material Sort`.
→ Label: **did the actual ISS smoke detector respond**. 5 materials (Kapton, Silicone,
Lampwick, Pyrell, Teflon).
→ This workbook **also contains the original SAME (PSI-102) flight results** in sheets
`SAME1 Flight Tests 8-27-09`, `SAME Ground Test Results`, `Flight-ground plot` — so
PSI-102 needs no further downloading.
→ Cleaning: heaviest wrangling of the clean datasets, but the numbers are real.

### Soot track

**PSI-107 — SPICE.** `microgravity_investigation/PSI-107/csv/`
`Spice.csv` = 470 rows of conditions, **no outcome**. The outcome is in
**`SmokePointReview-0g-3.xlsx`**, sheet `Smoke Point Datasheet` (~115 rows) — computed
**smoke-point flame length (SP)** per test plus fuel, nozzle diameter, flow rates,

`Spice_Flight_Flamelength.xls` holds ruler-calibration values for flame-length

→ Smoke point = sooting propensity. Fuels: ethylene, propane, propylene mixes.
Nozzles 0.41 / 0.76 / 1.6 mm.

### Solid materials track

**PSI-25 — BASS-II.** `microgravity_investigation/PSI-25/csv/BASS-II.csv`
129 ISS burns, 6 PIs. Materials: PMMA films/slabs/rods, SIBAL cotton-fiberglass
fabric, Nomex. Columns include calibrated initial/final O2, CO2, CO, radiometer gain,
fan/air settings.
→ **Highest value per row, worst formatting.** The outcome is not a column: extinction
and blow-off are written inside the free-text `Air display` field along with the flow
ramp (`5 down to ext`, `10 blowoff`) — 18 rows say it explicitly, the rest must be
inferred. `Fuel Sample Material` is free text with the same sample spelled three ways
(`2 cm 100 micron thick PMMA` / `2 cm 0.1 mm PMMA film` / `100 micron film 2 cm wide`).
Flow settings are multi-value ramp strings.
→ Budget roughly a day of hand-written mapping. Schedule **after** the clean datasets
are already working.

**PSI-99 — Saffire-II.** `microgravity_investigation/PSI-99/csv/SAFFIRE-2.csv`
Only 9 samples — far too few to train on — **but** each row carries the µg burn length
and spread rate *next to the 1-g result for the same material*. Silicone burns
completely on Earth and ~0 in microgravity; SIBAL spreads at 2.1–2.6 mm/s in both.
→ Use as a **display card** in the dashboard ("space fire ≠ Earth fire"), not training
data. Messy: `037 mm` typo, `Complete`/`Acceleratory` as values, explanatory notes as
trailing rows.

### Ground reference

**PSI-142 — Princeton counterflow.** `ground_investigation/PSI-142/csv/PSI data summary Princeton with links.xlsx`
~110 usable rows across sheets `data ID 1` (41 rows, cool-flame extinction strain rate
**with ozone**, 5 alkanes nC7→nC14), `data ID 2` (29, **without ozone**), `data ID 3`
(25, hot-flame extinction), `data ID 8` (14, peak temperature). Sheets `data ID 5/6/7`
are spatial profiles (~2,300 rows of signal vs distance) — curves, not per-condition
rows, skip.
`Data Summary Table.csv` is just an index of which figure in which paper each sheet
came from (useful for citations).
→ **This is 1g, counterflow burner, not ISS.** Any pooling must carry a `gravity`
column so the model never silently mixes regimes.
→ Also proof-of-concept that figure digitization works: Princeton did exactly that for
these 8 figures.

### Non-tabular

**PSI-115 — smoke CFD.** `ground_investigation/PSI-115/fields/` — 42 cleaned CSVs.
Each is a 240×960 grid (one variable, one case): temperature, smoke, velocity,
number density, nucleation rate, vorticity, species mass fraction. 5 cases:
8cm/10cm × gravity/no-gravity (+ a no-thermophoresis variant). `manifest.csv` records
each file's source path and parse status.
→ **Not training data** — 5 "rows" with 230,400 columns each. Two legitimate uses:
(1) side-by-side gravity vs microgravity heatmaps in the dashboard — visually the most
striking asset we have; (2) reduce each grid to a few scalars (peak temperature, plume
width, total particle count) for a 5-row summary table.
→ The two `NucRate` grids had ~50% `-inf` cells (log of zero outside the plume), now
NaN. **Do not fill those with 0** — "undefined" ≠ "zero nucleation"; that's a physical
decision for the user to make deliberately.

## 8. Architecture decision (agreed with the user, 2026-09-21)

**Do not build one model over all the data.** Each dataset answers a *different*
fire-safety question with different inputs and a different outcome; there is no shared
"risk" column, and inventing one would be dishonest. The dashboard is a set of small
modules, each with its own small interpretable model:

| Module | Data | Question |
|---|---|---|
| Suppression | PSI-69 | how much CO2/He does it take to put a fire out? |
| Cool flames | PSI-39 + PSI-117 | does an invisible flame persist after the visible one dies? |
| Sustainment | PSI-159 | does a gas flame keep itself alive or self-extinguish? |
| Detection | PSI-101 | will the smoke alarm actually trigger? |
| Soot | PSI-107 | how much smoke does this fuel make? |
| Materials | PSI-25 (+ PSI-99 card) | does this spacecraft material burn in space? |
| Ground reference | PSI-142 | extinction limits, ozone sensitization (1g) |

Plus two cross-cutting pieces: the **catalog view** (25 investigations, what each
contains, which have usable data — this is the "summarize and rank scattered data"
ask) and the **retrieval/grounding layer** (§9).

Recommended build order: **PSI-69 + PSI-39 first** (cleanest labels, same hardware,
and suppression is the most compelling story), then **PSI-159** (near-zero cleaning),
then detection and materials.

### Build approach — vertical slice (decided 2026-09-22)

The user asked whether to design the frontend and pick tools before coding. Answer:
**no, and there is no global "normalize everything" phase either.** Per §8 there is no
master table, so normalization is not a step before the code — it *is* the first third
of each module's code.

Build **one module thin, end to end** first: PSI-69 → clean → tidy table → model → one
deliberately ugly Streamlit page. The point is not the page, it's touching every layer
once so the later decisions are informed instead of speculative.

Why not frontend-first: the dashboard shows a prediction, and **we do not yet know if
the prediction is worth anything** (PSI-69's majority-class baseline is ~87%, so a
model scoring 88% has nothing to display). Designing UI around an unvalidated result
risks building something beautiful around nothing — and creates pressure to oversell
the model to justify the work. Cleaning a column you end up not needing costs hours;
that risk is much smaller.

## 9. Modeling plan and methodology caveats

**Classical ML, not deep learning.** Row counts are in the hundreds. Rule of thumb
used: 10–50 rows per feature. Prefer logistic regression or a shallow decision tree
(`max_depth≈3`) over ensembles at this N — an ensemble will memorize noise. Report
this as a stated methodological choice, ideally with a **learning curve** (accuracy vs
training-set size) to show statistical awareness rather than hiding small-N.

**Leakage caveat.** Where a dataset contains both experimental and model/simulation
rows for the same physical condition (PSI-117 does), those are **not independent**.
Split train/test **by physical condition, not by row**.

**Gravity caveat.** PSI-142 is 1g. Never pool it with ISS data without an explicit
`gravity` column.

**Provenance caveat.** If figure digitization is ever used to fill gaps (WebPlotDigitizer
is the standard tool; Camelot/pdfplumber/Docling for tables in PDF text), tag those rows
`source = digitized` so they can be evaluated with and without. A digitized point is a
reading of a reading.

**The retrieval / grounding layer** is the second distinct "AI" piece and what turns a
bare probability into something an engineer would trust: split the reports and papers
in the `reports/` folders into paragraphs, embed each paragraph, and at query time
return the nearest paragraphs to the prediction's context, with citation (document,
page). No fine-tuning, no training — nearest-neighbour search over text. Build it
**only after** at least one model works. There are ~40 PDFs already on disk across the
`reports/` folders; publication lists (title/authors/DOI) are captured in some
`info.md` files, no paywalled PDFs downloaded.

**Phase 3 (now worth doing, no deadline):** CV on raw video — droplet diameter from backlit frames
(threshold → contour → ellipse fit → pixel-to-mm calibration → plot (d/d0)² vs t
against the d-squared law). Saffire has the most dramatic footage. Still do not start this
before modules 1–3 work. It re-derives measurements the original papers already
computed — which is exactly why it is a good *learning* exercise and a poor deadline
task: the published number is ground truth for your own pipeline, so you can actually
check whether your CV is right.

### Handoff claims the data disproved

**PSI-39 — the label was wrong.** §6 said "120 of 227 … roughly balanced". In
truth 81 tests carry `Completed Analysis? = No` and are empty; counting them as
"no cool flame" trains the model to predict whether a test was *analysed*. And
among the 146 analysed, extinction diameter alone misses 7 tests that have a
cool burning rate without a recorded diameter. Honest label: kcool OR Dext,cool,
analysed tests only → **124/22 on 146 rows, 85/15, not balanced**. Also **all 44
farnesane tests are unanalysed** — that fuel yields zero modelable rows, so the
module has 3 fuels not 4. At 5 atm, 15 of 15 show a cool flame (perfect
separation → logistic regression will need regularisation). Good news: the messy
text `Pressure` column is irrelevant, `DATA` has a clean numeric one agreeing on
all 227 rows.

**PSI-159 — 272 rows not 333, and it is two experiments.** 61 tests carry `-`
instead of SE/FT. The two files do not share a schema: normal flames inject fuel
into an oxidising ambient, inverse flames inject oxygen into a fuel ambient —
mirror experiments whose composition columns do not map onto each other. The
loader keeps `flame_type`, pools only configuration-independent thermochemistry
(Tad, Zst, pressure, fuel), and leaves the rest empty for the other type.

**PSI-101 — it is a regression, not "did the detector respond".** No column
records an alarm. What exists is detector response in volts (continuous) plus
derived "concentration needed to trigger alarm X" thresholds. Inventing a cutoff
would be inventing the label. Also: the sheet holds **two campaigns** — 45 SAME
tests (= PSI-102, confirming nothing needs re-downloading) and 109 SAME-R. The
20 `DBP` rows are a calibration aerosol, not a spacecraft material.
Already visible in the data: **Teflon and Kapton produce the most particles but
the weakest scattering signal** (1.4 and 2.4 V vs 6.25 for silicone) — fine
smoke evades a scattering detector. That is a finding in itself.

**PSI-107 — 70 SPICE rows, not ~115, and three platforms are mixed.** The sheet
stacks four tables from **three different microgravity platforms** with no
header saying so: SPICE flight (55), KC-135 parabolic aircraft (6), Space
Shuttle STS-83/94 (31), SPICE Nikon series (15). Their gravity quality differs;
`platform` keeps them apart. Two "Avg" rows sit inside the shuttle block.
Physics check passed: propylene smoke-points at 31.5 mm vs propane 70.6 — an
alkene soots more than an alkane, so the columns are not scrambled.

**PSI-142 — the ozone condition is backwards in §6.** Princeton's own index says
data ID 1 is **without** ozone (Fig. 4), data ID 2 **with** (Fig. 5). §6 swaps
them; ozone sensitisation is the scientific point, so the swap inverts the
conclusion. Counts were right (41/29/25 = 95). 1g ground data, continuous
outcome → regression.

**PSI-117 — published-figure data, not raw runs.** NASA's ReadMe ties each file
to a DOI and figure. Every file mixes `Expt` with `Sim`/`Model` blocks **for the
same conditions** — the §9 non-independence, concretely. Rows tagged
`source` (experiment 69 / simulation 62 / error_bar 10); splits must be by
physical condition. Only `PROCI_2023_Alkane` has paired per-test rows (33, of
which just **15 experimental**). Four files, four different block conventions.

**PSI-25 — there is no usable label. The §8 "Materials" module cannot be
trained.** Two candidates, both fail. (1) The free-text outcome: only **20 of
129** cells state `ext` / `blowoff` / `no ign`; the other 109 hold a flow ramp
with no conclusion, and deducing extinction from a list of numbers would be
invention. (2) Oxygen consumed: physically impossible values — final O2 reaches
40.4%, delta ranges −19.7 to +20.6 (oxygen *appears*, the chamber was repurged
between readings), median 0.3 points. CO also has negative (−3 ppm) and censored
(`>500`, `over`) values. What PSI-25 *is* worth is a materials catalogue: 129
real ISS burns with geometry untangled from 51 spellings into 6 family/form
combinations, thicknesses 0.1–5 mm, rod diameters 1/4"–1/2" → 6.35/9.525/12.7 mm.
**Revise §8: the Materials module is descriptive, or it leans on PSI-99.**

**PSI-99 — the SIBAL half of the story is wrong, and the truth is better.** §6
says SIBAL "spreads at 2.1–2.6 mm/s in both". At 1g the column reads
`Acceleratory` — there is no steady rate. Microgravity gives constant spread
(2.1 then 2.6 mm/s); Earth gives acceleration. Two propagation regimes, not one
number. Silicone does confirm §6: 0 of 4 burned in microgravity.

**PSI-115 — the plume concentrates in microgravity.** Vorticity 56.8 at 1g vs
35.2 in µg, axial velocity 3.64 vs 2.40 — buoyancy drives both. But peak smoke
fraction is **14.2 in µg vs 7.5 at 1g** while spreading less: without buoyancy
the smoke does not leave, it sits near the source. Caveat: **no physical axes** —
the `*_sGrid_grid3d.dat` coordinate meshes still fail to parse (§5), so spreads
are in grid cells, not mm. Temperatures are **normalised** (1–1.577), not K.
NucRate grids are 39% and 52% defined; the undefined cells are log-of-zero
outside the plume and must never become 0.

### Other findings

* **PSI-159's `info.md` is an empty stub** (13 lines, all TBD) — the only one of
  the 24. Needs the user to paste NASA's description per the §4 verbatim rule.
  Consequence: its `TFP` column is undocumented anywhere.
* Encoding eats sub/superscripts across NASA files: PSI-69's `CO` is CO2, its
  `Burning rate; mm` is mm^2/s, PSI-99's `?-g` is µ-g. Always verify — the
  fraction-sum check in `clean.py` is what proved the CO2 reading.
* Two `add_provenance` bugs were found and fixed: it overwrote per-row `source`

  existing column. Both would have silently erased exactly the distinction that
  makes those tables worth having.
